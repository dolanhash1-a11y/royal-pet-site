# Royal Pet — сайт грумінг-студії

Проєкт працює як статичний сайт у GitHub Pages із підключеним Cloudflare Worker API. Дані кабінету зберігаються не в статичних JSON-файлах, а в бекенді Worker/D1.

## Основні частини

- `/` — головна сторінка Royal Pet.
- `/booking/` — онлайн-запис.
- `/cabinet/` — захищений кабінет студії.
- `cloudflare/royal-pet-admin-api-r2-final.js` — вихідний код Cloudflare Worker API.
- `content/breeds.json` — єдиний статичний довідник порід для форми запису.

## Послуги

Єдине джерело правди для послуг — таблиця `services` у D1 через API Worker.

У `Кабінет → Послуги` можна створювати, редагувати та видаляти послуги, вибирати тварину, групу, назву, ціну й опис.

На сторінці запису:

- для песиків доступні `Комплекс`, `Гігієна`, `Адаптаційний` та всі активні позиції з групи `Додаткові послуги`;
- для котиків доступні всі активні котячі послуги з кабінету;
- вибір виконується чекбоксами;
- дані вибраних послуг передаються в заявку разом з їхніми ID, назвами та цінами;
- ціни на сторінці запису приховані.

Після змін у кабінеті сторінка запису отримує актуальний каталог напряму через `/public/services`. Запит використовує `cache: no-store` і cache-busting параметр, щоб не використовувати старий каталог.

## Запис

Форма запису перевіряє вибрану дату та вільний час через API перед створенням заявки. Зайнятий слот повторно перевіряється сервером.

## Публікація

Для GitHub Pages використовується гілка `main`. Після змін GitHub Pages має завершити свій deployment автоматично.

Cloudflare Worker потрібно деплоїти окремо після змін у його вихідному файлі. Репозиторій містить саме вихідний код Worker, але факт його live deployment з цього середовища не перевіряється.

## Важливо

Не створювати нові дублікати booking-скриптів для тих самих функцій. Сторінка запису використовує один скрипт каталогу послуг (`booking/booking-services-picker.js`) та один скрипт доступності/відправки (`booking/booking-availability.js`).
